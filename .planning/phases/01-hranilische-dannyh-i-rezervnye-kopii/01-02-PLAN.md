<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-selected JSON file → parser/validator | File bytes and all fields are untrusted until complete validation succeeds. |
| Import service → IndexedDB | Validated data crosses into persistent user state only after explicit confirmation. |
| IndexedDB → backup serializer | Personal resume and vacancy data may leave browser storage only through a user-initiated export choice. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Tampering | backup parser, version dispatcher, restore service | high | mitigate | Strictly check marker/version, types, keys, IDs, timestamps, and limits; finish all validation before a single confirmed whole-state repository write. |
| T-01-03 | Denial of Service | selected backup file and nested arrays/strings | high | mitigate | Reject files over 10 MiB before reading and enforce array/string bounds before building preview or writing. |
| T-01-05 | Information Disclosure | export serializer | high | mitigate | Require explicit per-version inclusion flags for vacancy descriptions; omit unchecked fields and test serialized JSON contents. |
| T-01-SC | Tampering | npm package installation | high | mitigate | Retain the human package-legitimacy gate and exact lockfile established in Plan 01. |
</threat_model>
